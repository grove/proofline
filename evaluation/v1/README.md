# Proofline vNext — frozen six-task independent baseline

**Status: prepared; live ordinary-agent baseline NOT EXECUTED.**

This is a lightweight experimental gate for [issue #9](https://github.com/grove/proofline/issues/9), not a new Proofline runtime or verification stage. It reuses the lessons and accounting distinctions from the [13 October bounded comparison](../../docs/BOUNDED-COMPARISON.md) without reusing its task population or editing its original report.

## What has actually been frozen

- [protocol.json](protocol.json): six raw requests, one baseline arm, a specified model/host, execution order, budgets, outcome definitions, all-assigned denominators, stop rules, evaluator isolation and later matched-arm conditions.
- [tasks.py](tasks.py): six fresh tasks and tiny public JSON CLI/library/service seed projects. Each has an unchanged CLI `--version`/invalid-argument compatibility contract. Agents see **only** a generated task's `source.md` and `product/` directory.
- [oracle.py](oracle.py): literal expected behavior for valid inputs, boundaries and material negative cases, derived from the source requests rather than generated by candidate implementations.
- [variants.py](variants.py): six reference solutions, six algorithmically different valid alternatives, and six deliberate defects. These are **control fixtures**, not worker hints.
- [benchmark.py](benchmark.py): exercises all 18 trusted controls against the separate grader on library, service and CLI seams, including readback for source changes.
- [FREEZE.json](FREEZE.json): exact Git blob digests of the protocol, source corpus, oracle, controls, evaluator and original unexecuted ledger.
- [ledger.json](ledger.json): all six assigned tasks explicitly `NOT_EXECUTED`, without invented tokens, durations, human time or dollar costs.

All task/control/evaluator identities are frozen before any live dispatch.
The committed Git revision and Git blob identities must be read back by a
trusted coordinator before a future campaign. Changing any frozen input is
a new study version, not an amendment of baseline results.

## Reproduce the offline preparation (no models)

From the repository root:

```sh
python3 -B evaluation/v1/benchmark.py controls
python3 -B evaluation/v1/benchmark.py report
python3 -B evaluation/v1/benchmark.py seed collision-slugs /tmp/proofline-baseline-unique-run
```

The `controls` command runs **only bundled, trusted fixture implementations**
in local subprocesses. It must show six passing references, six passing valid
alternatives, and six detected material defects (18/18 controls matched).
It does not make model calls, time a live agent, test a model's reliability,
or grade arbitrary user/agent code.

**Security boundary:** Do not give a coding worker a checkout containing
`oracle.py`, `variants.py`, `FREEZE.json` or private result files. Withhold
the grader and its answer keys in host-protected paths and deny model access,
network, sibling assignments and the enclosing source checkout. The source
and grader are *publicly readable in this repository*, so this is **not** a
secret holdout against an agent with external GitHub access. A live campaign
must qualify the actual isolation and use the original independent checker
behind a native restricted execution boundary; the offline subprocess
control harness is **not safe to use on untrusted agent output**.

The fixed scorer uses finite CLI/library/service tests and exact unchanged
compatibility wrappers. It intentionally does **not** certify every possible
input, deployment behavior, external dependency, or full source promise.
The same study author wrote the task specifications and expected-output
fixtures, so independent means independent of workers/candidate code—not
a separate human author. Valid alternative implementations help expose
overfitted graders but do not establish universal soundness.

## Live baseline execution and outcome handling (not done)

For a future qualified run, the trusted coordinator must:

1. Confirm the exact frozen commit and `FREEZE.json` identities, run the
   18 native grader controls on the qualified host and validate protected
   grader-source isolation **before** dispatching any worker.
2. Create the six worker input directories with `seed`, each in the frozen
   order. Use one **ordinary Codex coding agent** per task: Codex CLI
   0.162.1, `gpt-6.1-sol`, high reasoning, one dispatch, no separate
   Proofline reviewer/prover, no repair, 900-second episode maximum, 600
   coding seconds, and the same recorded self-check guidance/budget for
   all assignments. If the exact model or host is unavailable, stop and
   preserve **unexecuted** assignments; do not silently substitute.
3. Freeze the actual candidate and native receipts. Run the private
   independent expected-behavior grader **only inside the qualified
   protected host environment**, not via unsandboxed `grade_trusted_control`.
   Separately observe model completion handoff and correct behavior.
4. Write a new immutable, outside-corpus result record for **every**
   assigned task, including failures, timeouts, missing usage, capacity
   errors and unexecuted tasks. Retain the candidate's exact identity,
   actual tested interfaces, command receipts, elapsed episode seconds
   and known token categories. Human/operator effort and grader
   preparation must be separately recorded, or marked unknown.
5. Publish independently correct deliveries / 6, false acceptances,
   unnecessary blocks, executed / 6, seconds and reported tokens
   per correct delivery (including failed attempts), plus limitations.
   If there are no observed correct deliveries, or metric values
   are incomplete, the corresponding rates/cost ratios remain **unknown**.
   Do not mistake unexecuted assignments for observed incorrect code.

**No live grading, model calls, correctness rate or model superiority
claim exists yet.** The accompanying `report` command intentionally
returns `null` rather than zero for unknown performance metrics.

## Comparing later vNext changes

A later agent+Proofline cohort must freeze its own version and matched host,
model, task/source bytes, grading controls and episode budgets **before**
dispatch. Report all assigned tasks and overhead, including wrong handoffs,
false blocks, unavailable runs, operator decisions and unknown tokens.
Do not reuse a stopped campaign, silently revise original scores, or
turn the six-task example into a 100+ assignment program without a new
specific decision. Six modest synthetic tasks have low statistical power
and limited relevance to large repositories or complex domain standards.
