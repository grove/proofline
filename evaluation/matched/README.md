# Issue #16: bounded matched 2×2 study

Four fresh tasks, four arms, sixteen fixed assignments; one selected model,
host, coding transport and cumulative time budget. This is a separate study,
not a continuation or oracle repair of S6 or v1.

The [protocol](protocol.json) declares exposure, order, budgets, denominator,
taxonomy, stop rules, resource accounting and decision criteria. The
[corpus](corpus.py) contains exact requests, seeds, independently authored
literal finite expectations and valid/alternative/defective controls. It
must remain inaccessible to coding workers. Every task has a batch obligation
omitted from repository tests. Defective controls pass those tests but omit
batch behavior. Dependency ordering also has a historical alphabetical test
that contradicts the new original-order request; correct controls repair it.

Proofline arms use the actual check-only runtime and feedback/status readback;
there is no correction arm. Intentline arms use one planning pass in the
same implementer's single turn, with its offline producer and real plan skill.
The combined arm additionally uses the actual optional JSON adapter. There is
no independent planner, reviewer, prover, adoption or approval stage. R labels
and unlinked rows are advisory; gaps do not block delivery. Commands and private
expected outputs are independent of generated inventories.

Offline checks, with no model dispatch:

```sh
/opt/homebrew/bin/python3.14 -B -m evaluation.matched.study controls
/opt/homebrew/bin/python3.14 -B -m evaluation.matched.study report
/opt/homebrew/bin/python3.14 -B -m unittest discover -s tests -p test_matched_study.py
```

`report` always shows the original unexecuted preparation ledger. Live evidence
is separate in ignored `.proofline/issue16-matched-v2-20261013/`. `qualify`
creates that directory once, checks exact host/model access, freezes all input,
runtime, producer and initial candidate identities, then exercises native
coding/grading canaries and all twelve controls. `execute` verifies those
identities before every dispatch and afterward. Both refuse reuse; no stopped
campaign can resume. Missing or unavailable attempts retain their assigned slots.

An isolated worker receives only its request, product and common selected
commands, plus a pinned read-only producer in the planning arms. Native profiles
deny enclosing repository, grader, controls, private receipts, siblings and
network. Private expected outputs never enter candidate execution: only public
inputs cross the grading boundary. The bare offline harness executes bundled
trusted fixtures only; never use it to grade an arbitrary candidate.

The study author also authored the finite oracle, independently of workers;
there is no second human oracle author. Algorithmic alternatives share validators.
Backend model revision and provider-internal calls are unavailable. Equal time
caps are enforced; a total token cap is not available in this transport. Four
tasks and descriptive task-bootstrap intervals cannot establish general
superiority, semantic completeness or synergy. Unknown prices, attention and
initiating-agent usage remain unknown. No additional mandatory action follows
from an inconclusive comparison.
