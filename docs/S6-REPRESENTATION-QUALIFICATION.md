## Mechanism and necessity

The last false acceptances shared an equality-capable score assumption with the
manually authored public predicates. The new `checks/metamorphic.py` compiler
accepts a source-declared unary library interface, ordering field paths and
source-valid samples. It systematically varies each field independently between
its original representation, a minimal less-than-only Python representation and
one whose equality operation raises. It compares normalized behavior against
the ordinary representation. For two independently declared fields, each sample
has nine representation combinations. It contains no task names, sorting answers,
benchmark paths or private evaluator inputs. An unrelated list-ordering example
passes, while numeric negation fails.

The caller still has to justify the relation from the source. Invariance can
reproduce an incorrect baseline result, so it cannot replace independently
adjudicated output invariants or complete-source reasoning. It also cannot
establish coverage of untested values or relations. A source that legitimately
requires equality or arithmetic cannot be assigned an ordering-only relation.
The implementation uses the existing source-evidence-v1 transport: generated
Python is sealed into the source-bound criterion probe, with the same protected
inputs, candidate binding and exact successful native citations. It adds no model
stage, dependency, effect authority or acceptance shortcut.

The exposed pagination profile replaces its hand-selected operator-type loop
with this general representation relation. Source-authored samples are separate
from private grader inputs. Its independently derived order, multiplicity,
field, paging, malformed-row and integer-subclass invariants remain. The
independent public-library grader is retained, so a transformation pass cannot
supersede a reproduced product defect.
