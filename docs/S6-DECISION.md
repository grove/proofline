# S6 decision — abandon certification, simplify execution

13 October 2026. **S6's decision phase is closed under the owner's revised scope.**
Automated full-promise certification is abandoned. Proofline now supports one
bounded coding attempt followed by explicit executable checks. **The original
full comparisons remain incomplete.** This closure is not a passing trust gate,
a completed comparison, or evidence of efficiency/model superiority.

## Scope and authority

The owner asked whether the prolonged work could be simplified to finish in
reasonable time. The proposed scope was to close S6 with an abandon decision,
preserve the original comparisons as incomplete, then simplify Proofline to a
bounded coding runner reporting explicit checks. It explicitly replaced the
original full-comparison completion requirement. The owner selected:

> Close S6 with that decision (Recommended)

The exact question/answer is retained in
`.proofline/s6/scalar-qualification-v1/operator/scope-change-authorization.json`.
Original task promises, historical reports and experiment outcomes were not
rewritten. No contract adoption, remote publication or other effect authority
was created by this decision.

contexts, exact candidate bindings, executable receipts and isolation. Unary
negation narrowed sortable scores to numbers; equality narrowed ordering values;
string-instance methods narrowed valid text subclasses. Source-blind evidence
authors also produced unusable designs, wrong expectations and narrower coverage.
Manually supplied public predicates shared some of those assumptions. Increasing
finite coverage repaired controls but did not establish general source coverage.

This evidence supports abandoning the universal-certification hypothesis and

## The smaller product

`proofline.py run --repo ... --source ... --checks ...` reuses the native coding
transport for one attempt on an isolated Git snapshot. It preserves the exact
request and caller-selected command argument lists, freezes the candidate, then
runs those commands under the read-only native boundary within the cumulative
budget. It records command outcomes, native receipts, model usage and the candidate.
Failed checks and unavailable executions remain separate. `status` rejects stale
candidate/source/check inputs and mismatched command receipts.

There is no automatic reviewer, prover, recovery loop, publication or merge in
this workflow. CHECKS PASSED means only that the listed commands exited
successfully. The caller decides whether the full request is fulfilled. Historical
delivery/resume require `--experimental`; their prior source/adoption/effect gates
remain, and their model verdicts are explicitly untrusted for full-source coverage.
Existing research code and all raw evidence are retained rather than deleted.

The [README](../README.md), [design](../DESIGN.md),
[implementation roadmap](../IMPLEMENTATION.md) and [skill](../SKILL.md) now describe
this scope. Earlier design/usage text was preserved privately before the change.
No dependency, task answer key or additional model assurance stage was added.
