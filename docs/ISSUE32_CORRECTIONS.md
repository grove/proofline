# Making Sol findings executable

The primary study keeps its original repair rule: one correction on the same
Luna thread requires an intact, candidate-bound Proofline assertion failure in
immutable public check 0. Sol rereads the whole source and can explain that
failure, but cannot authorize repair. A suspected omission with green selected
checks remains an observed limitation. Expanding the oracle after seeing model
results would change the experiment.

The smallest useful follow-up is **selection from frozen, independently
qualified public probes**, not execution of Sol-authored expectations. Before
dispatch, declare a short probe table with input, exact expected output/type,
original-source quote, executable command and hashes. Each expected result must
either be an explicit literal example in the source or be independently derived
and checked against correct, alternative and deliberately defective controls.
If neither route establishes the expectation, the probe is unavailable. A
verbatim quote or a model's plausible derivation is insufficient. Keep this
public table separate from the unchanged private grading vectors.

Sol receives the complete original request, frozen implementation and actual
receipts, without the earlier plan. It may nominate one table entry for a
concrete defect, citing the original clause. The trusted controller validates
the entry and its source identity, executes the frozen command under the
qualified native sandbox and validates the receipt against the exact candidate.
Only a genuine assertion failure may trigger the existing one-attempt same-Luna
correction. Missing probes, unavailable isolation, timeouts, unverified links,
changed candidate bytes and green checks do not qualify. Freeze and recheck the
corrected candidate; independently grade both candidates. Never send private
grades or their expectations to either model.

For example, a missing `service.batch` requirement could be corroborated by a
predeclared empty-batch probe whose `[]` expectation is grounded in the original
batch contract and independently validated. Sol discovering a new invoice
rounding example during verification cannot invent its expected total and use
that to authorize repair. It must select an already qualified probe or leave
the finding advisory.

This is a **proposed, unimplemented, unauthorized comparison**. Freeze its probe
table, prompts, budget and denominator separately. Include a checks-only
comparison that runs the same extra probes without Sol: otherwise a gain could
come entirely from better tests, and Sol's marginal value would remain unknown.
Expose the same public expectations to comparable coding arms before dispatch.
Include probe construction, qualification, selection, checks, review and repair
in cost accounting. Do not merge these results with the primary 20 assignments.

Until that comparison is authorized, use the existing mechanism and report
missed requirements honestly. No extra reviewer, model judge or production
workflow stage is needed.
