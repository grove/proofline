# Issue #16 matched comparison: preparation, not efficacy evidence

13 October 2026. **Empirical acceptance INCOMPLETE.** Four fresh tasks and a
matched 2×2 protocol are implemented; all twelve offline controls matched.
Native qualification stopped before any model dispatch. All **16/16 assigned
slots remain NOT_EXECUTED**, with no observed correctness rates, token usage,
episode seconds, false acceptances or blocked-delivery estimates.

The [protocol](../evaluation/matched/protocol.json) fixes original requests,
projects and preexisting tests, independent literal finite expectations,
correct/alternative/defective controls, arm order and exposure, model/host,
equal budgets, source/base identities, stop rules and all-assigned accounting.
Each task contains an untested batch obligation. The deliberately incomplete
controls pass repository tests but fail the private batch observations. Other
cases cover negative validation, compatibility, intermediate overdrafts,
empty-but-found translations, case sensitivity, disconnected cycles, FIFO
update order and zero capacity. A stale alphabetical node-order assertion
conflicts with the source; correct controls repair it. Plausible conventional
locale-grammar/default-truncation assumptions are explicitly falsified.

The ordinary, Proofline-only, Intentline-only and combined arms share the same
raw request, starting bytes, underlying Codex model/host and public check
definitions. Planning is one semantic pass within the same coding turn, using
the pinned Intentline producer/skill; its capture, draft and export consume
the same 600-second agent allocation within the 900-second episode. Proofline
uses actual `check`/feedback/`status`, and the combined arm uses the optional
JSON adapter. No second planner, reviewer, prover, correction, adoption or
approval stage is required. The protocol deliberately measures one-handoff
checking; it does not estimate the qualified optional #15 correction path.

## Why execution stopped

The original freeze is retained at commit
`4ae912fafeb5f9203257b2efda48045593a335a8` and in
[preflight.json](../evaluation/matched/preflight.json), with all original frozen
study sources retained in [preflight-source.zip](../evaluation/matched/preflight-source.zip)
so provenance also survives a squash merge. Qualification observed
denials for source/Git/receipt writes, actual grader/root/private reads and
network, with candidate/scratch writes allowed. However its `sibling` read
target was mistakenly the **same allowed worker candidate**. Reading it
succeeded, contradicting the authored expected denial. This is a harness
expectation error, not evidence of a native isolation breach or missing model
access. The native preflight therefore correctly refused qualification.

No worker ever received a request, no live model was dispatched, no grading
control ran natively and no empirical delivery was scored. The declared
stop-on-invalid-boundary/control rule applies: the original failed preflight,
seed/source identities and all sixteen missing runs remain visible. There
was no replacement case, model substitution, S6 resumption or silent oracle
repair. A fresh-clone lifecycle guard now prevents v2 qualification/execution;
fixing the canary setup does not authorize a retry of this frozen study.

The current preparation code points that canary at a genuinely separate
sibling fixture. Regression checks exercise the corrected setup without
dispatching models or resuming v2. Current preparation hashes and original
failed-freeze hashes are distinguished. A fresh authorized declaration and
successful controls at the actual planning/coding/check/grading boundaries
are still required before any future live cohort.

The [standalone corrected-canary receipt](../evaluation/matched/corrected-canary.json)
observed every protected read denied and the intended product/scratch writes
allowed. It used the actual workspace storage boundary; it is a process
regression, not a grading control, model qualification or assignment result.
